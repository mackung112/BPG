UNIT 03 • WEBSITE GRAPHIC ASSETS PRODUCTION, VECTOR ICONS, IMAGE RETOUCHING & WEBP OPTIMIZATION

บทที่ 3: การสร้างและตกแต่งกราฟิกสำหรับเว็บไซต์
(Logo, ชุดไอคอน SVG, ไดคัทสร้างเงา และ WebP)

เปลี่ยนจากกล่องสี่เหลี่ยมสีเทากากบาท X ในขั้น Wireframe สู่การผลิต “สินทรัพย์กราฟิกของจริง (Production Graphic Assets)” ตั้งแต่การสร้างโลโก้และไอคอนเวกเตอร์บนตาราง 24px การไดคัทและสร้างเงาเสมือนจริง 2 ชั้นบน Photoshop ไปจนถึงการบีบอัดไฟล์ภาพเป็นฟอร์แมต WebP น้ำหนักเบาต่ำกว่า 150 KB

🎯

จุดประสงค์การเรียนรู้ประจำหน่วยที่ 3

1. ด้านความรู้ (Knowledge) 🧠
  • อธิบายความแตกต่างระหว่างภาพแบบ Raster (Bitmap) และ Vector Graphic รวมถึงโครงสร้างโค้ดเชิงตรรกะของไฟล์ SVG (Scalable Vector Graphics) ได้อย่างถูกต้อง
  • อธิบายหลักการยศาสตร์และมาตรฐานการสร้างชุดไอคอนบนโครงตาราง 24px Icon Grid และการควบคุมความหนาเส้น (Stroke Weight) ได้
  • อธิบายหลักทฤษฎีแสงเงาการตกแต่งภาพเชิงพาณิชย์ ได้แก่ เงาสัมผัสพื้น (Contact Shadow) และเงาทอดยาว (Cast Shadow) ได้อย่างสมจริง
  • เปรียบเทียบคุณสมบัติ ความคุ้มค่า และการกินแบนด์วิดท์ของฟอร์แมตไฟล์ภาพดิจิทัล (JPEG, PNG, WebP, AVIF, SVG) ได้
  • อธิบายความสัมพันธ์ระหว่างขนาดไฟล์ภาพ (File Size) กับค่าดัชนีความเร็วของเว็บไซต์ (Core Web Vitals: LCP) และผลกระทบต่อ SEO ได้
2. ด้านทักษะปฏิบัติการ (Skill) 🛠️
  • งานกราฟิกเวกเตอร์และไอคอน: ออกแบบโลโก้ร้านค้าและวาดชุดไอคอนเวกเตอร์บริการ 4 แบบ (จัดส่งฟรี, รับประกัน, ชำระเงินปลอดภัย, บริการ 24 ชม.) บนโครงตาราง 24px และส่งออกเป็นโค้ด SVG ที่สะอาดได้
  • งานตัดต่อและรีทัชภาพสินค้า: ใช้เครื่องมือ Pen Tool และคำสั่ง Select and Mask ใน Adobe Photoshop ทำการตัดต่อ (ไดคัท) พื้นหลังสินค้า 4–6 รายการ พร้อมปรับแต่งสีและสร้างเงาเสมือนจริง แล้วนำไปประกอบลงในการ์ดสินค้าบน Figma ได้
  • งานบีบอัดภาพและตรวจสอบขนาดไฟล์: ปรับขนาดมิติพิกเซลของภาพสินค้า บีบอัดเป็นฟอร์แมต WebP ให้มีขนาดไฟล์ต่ำกว่า 150 KB โดยสายตามนุษย์ยังมองเห็นความคมชัด พร้อมจัดทำตารางบันทึกการลดขนาดไฟล์ (File Size Audit Table) ได้อย่างสมบูรณ์
3. ด้านจิตพิสัย (Attitude) 💎
  • มีความประณีต อดทน และละเอียดรอบคอบในการควบคุมเส้นทางเดินของ Pen Tool เพื่อเก็บขอบชิ้นงานไม่ให้มีรอยแหว่งหรือขอบขาวหลุดลอย
  • มีจิตสำนึกในการเคารพกฎหมายลิขสิทธิ์รูปภาพและทรัพย์สินทางปัญญาในการนำภาพถ่ายสินค้ามาใช้งาน
  • คำนึงถึงผู้ใช้งานปลายทางที่มีอินเทอร์เน็ตความเร็วจำกัด ด้วยการบีบอัดไฟล์ภาพให้เล็กที่สุดก่อนนำขึ้นเว็บไซต์

INTRODUCTION • GRAPHIC ASSETS & WEB PERFORMANCE (CORE WEB VITALS: LCP)

บทนำ: สินทรัพย์กราฟิก (Graphic Assets) กับความเร็วของเว็บไซต์ (Web Performance)

ในหน่วยที่ 2 นักศึกษาได้สร้างโครงสร้างและพิมพ์เขียวหน้าแรกเว็บไซต์ (Wireframe) พร้อมระบบนำทางและการ์ดสินค้าบน Figma กันไปแล้ว แต่กล่องรูปภาพทั้งหมดยังคงเป็นเพียง “กล่องสี่เหลี่ยมสีเทาที่มีกากบาท X” เมื่อก้าวเข้าสู่ หน่วยที่ 3 เราจะเริ่มต้นผลิต “สินทรัพย์กราฟิกของจริง (Production Graphic Assets)” โดยมีสถิติวิจัยพฤติกรรมผู้บริโภคบนเว็บไซต์จาก Google & Akamai ที่ต้องตระหนักดังนี้:

STAT 01 • PATIENCE LIMIT > 3 วินาที

1. ความอดทนของลูกค้า

STAT 02 • CONVERSION LOSS -7% / วินาที

2. ผลกระทบต่อยอดขาย

ทุกๆ 1 วินาที ที่เว็บโหลดช้าลง ยอดขายออนไลน์ (Conversion Rate) จะลดลงเฉลี่ย 7%

STAT 03 • BANDWIDTH CULPRIT 65% – 70%

3. ตัวการที่ทำให้เว็บโหลดช้า

กว่า 65% – 70% ของปริมาณข้อมูลทั้งหมดที่เว็บต้องดาวน์โหลด มาจาก “ไฟล์รูปภาพและกราฟิกที่ไม่ได้ผ่านการบีบอัดอย่างถูกวิธี”

PART 01 • VECTOR LOGO, BÉZIER CURVES, SVG XML & 24PX ICON GRID

ตอนที่ 1: งานกราฟิกเวกเตอร์ โลโก้ และชุดไอคอนบริการ (Vector Logo & SVG Icons)

เข้าใจความแตกต่างเชิงโครงสร้างระหว่างภาพราสเตอร์ (Raster Pixels) กับภาพเวกเตอร์ (Vector Bézier) โครงสร้างโค้ด SVG กฎเหล็ก 24px Icon Grid และการออกแบบชุดไอคอนบริการ 4 รูป

TOPIC 1.1 • RASTER PIXELS VS VECTOR BÉZIER GRAPHICS

1.1 มหากาพย์ภาพราสเตอร์ (Raster Pixels) ปะทะ ภาพเวกเตอร์ (Vector Bezier)

โลกของกราฟิกดิจิทัลถูกแบ่งออกเป็น 2 อารยธรรมใหญ่ที่มีกลไกการสร้างภาพแตกต่างกันอย่างสิ้นเชิง:

ประเด็นการเปรียบเทียบ 🖼️ ภาพราสเตอร์ / บิตแมป (Raster) ✒️ ภาพเวกเตอร์ (Vector Graphics)
1. หน่วยโครงสร้างภาพ เม็ดสีตารางพิกเซล (Grid Pixels) สูตรสมการคณิตศาสตร์เส้นโค้ง (Bezier)
2. เมื่อซูมขยายภาพ ภาพแตกเป็นเม็ดฟันปลา (Pixelated) คมกริบ 100% ทุกระดับการซูมและทุกจอภาพ
3. ความเหมาะสมในการใช้งาน ภาพถ่ายบุคคล, ภาพวิว, สินค้าจริง โลโก้, สัญลักษณ์, ไอคอน, ฟอนต์ตัวอักษร
4. นามสกุลไฟล์ยอดนิยม .jpg, .png, .webp, .gif .svg, .ai, .eps
5. ขนาดไฟล์ตามขนาดหน้าจอ ยิ่งภาพกว้าง ขนาดไฟล์ยิ่งใหญ่ ขนาดไฟล์คงที่ ไม่ว่าจะแสดงผลเล็กหรือใหญ่
🔍 ทดลองซูมขยายภาพ (Zoom Loupe: 1x → 4x → 8x)
Raster (Grid Pixels)
ซูมขยายจะเห็นเม็ดสีแตกเป็นขั้นบันได
Vector (Bézier Curve)
คมกริบ 100% ทุกการซูมเพราะคำนวณจากสมการ
📐 สูตรสมการเส้นโค้งเบซิเยร์ (Bézier Curve Mathematics)

คอมพิวเตอร์ไม่ได้จำว่าเส้นโค้งมีสีกี่เม็ด แต่จำ “พิกัดจุดเริ่มต้น (P₀), จุดควบคุมทิศทาง (P₁), และจุดสิ้นสุด (P₂)” ผ่านสมการพหุนาม:

B(t) = (1 - t)²·P₀ + 2(1 - t)t·P₁ + t²·P₂   (0 ≤ t ≤ 1)

นั่นคือเหตุผลที่ไฟล์เวกเตอร์มีขนาดเล็กมากเพียงไม่กี่กิโลไบต์ (KB) เพราะเก็บเฉพาะข้อมูลตัวเลขพิกัด ไม่ได้เก็บเม็ดสีนับล้านเม็ดเหมือนภาพถ่าย

TOPIC 1.2 • SCALABLE VECTOR GRAPHICS (SVG XML CODE)

1.2 เจาะลึกไฟล์ SVG (Scalable Vector Graphics) ทำไมเว็บยุคใหม่ถึงขาดไม่ได้?

SVG ไม่ใช่แค่ไฟล์รูปภาพธรรมดา แต่เป็น “โค้ดข้อความภาษา XML (eXtensible Markup Language)” ที่เว็บเบราว์เซอร์สามารถอ่าน เข้าใจ และประมวลผลเป็นภาพได้โดยตรง:

<!-- ตัวอย่างโค้ด SVG ไอคอนรถส่งของ ที่เบราว์เซอร์อ่านจริง --> Size: ~320 Bytes 
<svg xmlns="http://www.w3.org/2000/svg" width="24" height="24" viewBox="0 0 24 24"
     fill="none" stroke="#111827" stroke-width="2" stroke-linecap="round" stroke-linejoin="round">
  <rect x="1" y="3" width="15" height="13" rx="2" />
  <polygon points="16 8 20 8 23 11 23 16 16 16 16 8" />
  <circle cx="5.5" cy="18.5" r="2.5" />
  <circle cx="18.5" cy="18.5" r="2.5" />
</svg>
⚡ ทดลองเปลี่ยนสีไอคอนผ่าน CSS โดยไม่ต้องวาดรูปใหม่
1. Resolution Independence
ความคมชัดระดับอินฟินิตี้

ไม่ว่าจะเปิดบนจอมือถือราคาประหยัด หรือจอ 5K Retina Display ภาพไอคอนจะคมกริบเสมอ ไม่มีวันแตกเบลอ

2. Ultra-Tiny File Size
ขนาดไฟล์เล็ก 500B – 1.5 KB

ไอคอน 1 ตัว มีขนาดโค้ดเพียง 500 ไบต์ ถึง 1.5 KB เท่านั้น (เล็กกว่าไฟล์ภาพ PNG ถึง 10–20 เท่า)

3. CSS Styleable
ควบคุมสีสันได้ผ่าน CSS

สั่งเปลี่ยนสีไอคอนเมื่อเมาส์ชี้ได้ทันที เช่น svg:hover { stroke: #7C3AED; } โดยไม่ต้องวาดรูปใหม่

4. Zero HTTP Overhead
ความเร็วในการโหลดสูงสุด

เบราว์เซอร์ประมวลผลโค้ด SVG ร่วมกับ HTML ได้ทันทีโดยไม่ต้องส่งคำขอไปดึงไฟล์ภาพแยกจากเซิร์ฟเวอร์

TOPIC 1.3 • THE 24PX ICON GRID SYSTEM & 2PX STROKE

1.3 ระบบโครงตารางไอคอนมาตรฐาน (The 24px Icon Grid System)

ในอุตสาหกรรมระดับโลก (เช่น Google Material Symbols, Lucide Icons, Feather Icons) ได้กำหนดมาตรฐานกลางไว้คือ ระบบตาราง 24 × 24 พิกเซล เพื่อให้ไอคอนทุกตัวมีขนาดและน้ำหนักสายตาสม่ำเสมอกัน:

📐 โครงสร้างตารางไอคอนมาตรฐาน (24×24px Canvas) Live Area: 20×20px
Padding ปลอดภัย 2px รอบทิศ
Live Area (20 × 20 px) Stroke Weight: 2px • Round Cap/Join
กรอบนอกสุด (สีแดง) = 24 × 24 px  |  พื้นที่วาดจริง (สีเขียว) = 20 × 20 px

🛠️ กฎเหล็ก 4 ข้อในการสร้างชุดไอคอนเวกเตอร์:

1. ขนาดเฟรมตายตัว (24 × 24 px Frame)

ตั้งขนาด Frame เป็น 24 × 24 px เสมอ เพื่อให้จัดวางเข้ากับระบบ 8-Point Grid บนหน้าเว็บได้พอดี

2. ขอบเขตปลอดภัย (Padding 2px รอบทิศ)

เนื้อหาของไอคอนต้องอยู่ภายในพื้นที่ 20 × 20 px ห้ามวาดชนขอบ 24px สนิท เพื่อป้องกันไม่ให้ขอบของเส้นถูกตัดแหว่งเมื่อ Export

3. ความหนาเส้นสม่ำเสมอ (Consistent Stroke Weight = 2px)

ไอคอนทุกตัวในแบรนด์ต้องใช้ความหนาเส้นเท่ากันทั้งหมด โดยแนะนำที่ 2px (หรือ 1.5px สำหรับสไตล์มินิมอล)

4. จุดมุมและปลายเส้นมน (Rounded Caps & Joins)

ตั้งค่า Stroke Cap = Round และ Stroke Join = Round เพื่อให้เส้นโค้งมน นุ่มนวล สบายตา

TOPIC 1.4 • 4 SERVICE TRUST ICONS KIT & FIGMA WORKFLOW

1.4 ปฏิบัติการออกแบบชุดไอคอนบริการ 4 รูป (Service Trust Icons)

1. ไอคอนจัดส่งสินค้า

STEP 01 • สร้าง Frame 24×24px

กด F ลาก Frame สี่เหลี่ยมจัตุรัสขนาด 24 × 24 px

STEP 02 • ซูมเต็มจอ (Shift + 2)

คลิกเลือกเฟรมแล้วกดปุ่ม Shift + 2 เพื่อขยายวัตถุที่เลือกให้เต็มหน้าจอทำงาน

STEP 03 • Vector Edit Mode

กด O หรือ R วาดรูปทรงพื้นฐาน แล้วกดปุ่ม Enter เพื่อเข้าสู่โหมดแก้ไขจุดเวกเตอร์ ดัดแปลงส่วนปลายเส้น

STEP 04 • Boolean Groups

รวมรูปทรงด้วยคำสั่ง Boolean ด้านบนกลางจอ: Union (รวมเป็นชิ้นเดียว) หรือ Subtract (เจาะตัดส่วนที่ทับซ้อนออก)

STEP 05 • Outline Stroke

ก่อนส่งออก คลิกขวาที่เส้นเลือก Outline Stroke (Ctrl + Shift + O) เพื่อให้เส้นกลายเป็น Fill ป้องกันความหนาเส้นเพี้ยน

STEP 06 • Export เป็นไฟล์ .SVG

ที่แผงขวาล่างหัวข้อ Export เปลี่ยนจาก PNG เป็น SVG คลิก ... ติ๊ก “Include 'id' attribute” แล้วกด Export

TOPIC 2.3 • 2-LAYER COMMERCIAL SHADOW CRAFTING

2.3 ทฤษฎีแสงเงาเสมือนจริงสำหรับสินค้าบนเว็บ (Commercial Shadow Crafting)

หากนำภาพสินค้าที่ไดคัทแล้วมาวางบนพื้นขาวเฉยๆ สินค้าจะดู “ลอยอย่างไร้น้ำหนัก เหมือนภาพตัดแปะราคาถูก” นักออกแบบมืออาชีพต้องสร้างเงาเสมือนจริงขึ้นมา 2 ชั้น เสมอ:

✅ เปิดเงาครบ 2 ชั้น: สินค้าวางติดพื้นระนาบอย่างมีน้ำหนักสมจริง
📦 PRODUCT BOX
1. Contact Shadow: Opacity 80–90%, Blur 2–3px ชิดใต้ฐาน
2. Cast Shadow: Opacity 20–30%, Gaussian Blur 15–25px
ชั้นที่ 1 • Contact Shadow (เงาสัมผัสพื้น) Opacity 70%–85%
  • สร้าง Layer ว่างใหม่ไว้ “ใต้เลเยอร์สินค้า” ตั้งชื่อว่า Contact_Shadow
  • เลือกแปรงพู่กัน Brush Tool (คีย์ B) หัวนุ่ม (Hardness 0%) สีดำสนิท
  • บีบหัวแปรงให้แบนลงในพาเนล Brush Settings ปรับความกว้างให้พอดีกับฐานของสินค้า
  • คลิกแตะเบาๆ 1–2 ครั้งตรงจุดที่ก้นสินค้าสัมผัสพื้น ปรับค่า Layer Opacity ประมาณ 70% – 85%
ชั้นที่ 2 • Cast Shadow (เงาทอดตัว) Blur 15–25px • Opacity 20%–30%
  • สร้าง Layer ว่างใหม่อีกชั้นไว้ใต้ Contact Shadow ตั้งชื่อว่า Cast_Shadow
  • ใช้เครื่องมือ Elliptical Marquee Tool วาดวงรีแนวนอนใต้ตัวสินค้า เทสีดำลงในวงรีแล้วกด Ctrl + D
  • ไปที่เมนู Filter → Blur → Gaussian Blur ปรับค่ารัศมีความเบลอประมาณ 15px ถึง 25px
  • ปรับ Layer Opacity ลงเหลือเพียง 20% ถึง 30% จะได้เงาทอดตัวที่นุ่มนวลเป็นธรรมชาติที่สุด
TOPIC 2.4 • COLOR GRADING, S-CURVE (CTRL + M) & VIBRANCE

2.4 การเกรดสีและปรับแสง (Color Grading & Curves)

ก่อนนำภาพสินค้าไปใช้ ต้องปรับแต่งโทนภาพให้กลมกลืนกับ Mood & Tone และ Palette สีประจำแบรนด์ที่กำหนดไว้ในหน่วยที่ 1:

1. ปรับความสว่างและคอนทราสต์ด้วย Curves (Ctrl + M) S-Curve

ดึงเส้นกราฟเป็นรูปตัว S เล็กน้อย (S-Curve) โดยยกจุด Highlight ด้านบนขึ้นเล็กน้อย และกดจุด Shadow ด้านล่างลงเล็กน้อย เพื่อเพิ่มมิติความลึก จุดไฮไลต์สว่างคมชัด และเงามีน้ำหนักไม่แบนราบ

TOPIC 3.1 • WEB IMAGE FORMATS SHOWDOWN

3.1 ศึกชิงแชมป์ฟอร์แมตไฟล์ภาพบนเว็บ (JPEG vs PNG vs WebP vs SVG)

การเลือกใช้นามสกุลไฟล์ภาพผิดประเภท คือสาเหตุอันดับหนึ่งที่ทำให้เว็บไซต์โหลดช้าจนลูกค้าหนี:

ฟอร์แมตไฟล์ พื้นหลังโปร่งใส (Transparency) ระดับการบีบอัด (Compression) การรองรับเบราว์เซอร์ สถานการณ์การใช้งานที่ถูกต้อง
1. JPEG (.jpg) ❌ ไม่รองรับ (พื้นหลังทึบขาว) ปานกลาง (Lossy) 100% (ทุกอุปกรณ์) ภาพถ่ายวิวทิวทัศน์ทั่วไป (ยุคเก่า)
2. PNG (.png) ✅ รองรับ (โปร่งใสเนียน) ต่ำ (Lossless • ไฟล์มีขนาดใหญ่) 100% (ทุกอุปกรณ์) ภาพไดคัทที่ต้องการความคมชัดสูงสุด (แต่ไฟล์หนักมาก ไม่เหมาะกับเว็บช้า)
3. WebP (.webp) ⭐ พระเอก ✅ รองรับ (โปร่งใสสมบูรณ์) สูงมาก (เล็กกว่า JPEG 30% / เล็กกว่า PNG 80%) 97%+ (Chrome, Safari, Edge, Firefox) มาตรฐานสูงสุดของเว็บยุคปัจจุบัน ใช้กับภาพสินค้าไดคัทและแบนเนอร์ได้ดีเยี่ยม
4. SVG (.svg) ✅ รองรับ (โปร่งใสในตัว) สูงที่สุด (เก็บเป็นโค้ด XML) 100% (ทุกเบราว์เซอร์) ใช้เฉพาะไอคอน โลโก้ ลายเส้นกราฟิก (ห้ามใช้กับภาพถ่ายสินค้าเด็ดขาด)
💡 ทำไม WebP (พัฒนาโดย Google) จึงชนะขาดลอย?

WebP ใช้อัลกอริทึมการบีบอัดขั้นสูงที่เรียกว่า Predictive Coding (การทำนายค่าพิกเซลข้างเคียง) ทำให้สามารถลดขนาดไฟล์ลงได้มหาศาลโดยที่ตามนุษย์มองไม่เห็นความแตกต่างของเม็ดสี และยังรองรับความโปร่งใส (Alpha Transparency) เหมือน PNG แต่ขนาดไฟล์เบาเทียบเท่าหรือเบากว่า JPEG

TOPIC 3.2 • 72 PPI MYTH VS RETINA DISPLAY 2X ASSET RULE

3.2 ความเข้าใจผิดเรื่อง Resolution: 72 PPI vs หน้าจอ Retina 2x

ความจริงข้อที่ 1: 72 PPI vs 300 PPI บนหน้าจอเว็บ

สำหรับเว็บเบราว์เซอร์ ค่าตัวเลข 72 PPI หรือ 300 PPI ไม่มีผลต่อขนาดไฟล์หรือความคมชัดบนหน้าจอแม้แต่น้อย! (PPI ใช้สำหรับสั่งหัวพิมพ์ลงกระดาษเท่านั้น) สิ่งเดียวที่กำหนดขนาดและความคมชัดบนหน้าจอคือ มิติความกว้างคูณความสูง (Pixel Dimensions: Width × Height in Pixels)

ความจริงข้อที่ 2: มาตรฐานจอเรตินา (Retina Display 2x)

สมาร์ตโฟนและแล็ปท็อปยุคใหม่มีความหนาแน่นพิกเซลสูงกว่าปกติ 2 เท่า (2x) หากการ์ดสินค้าบนหน้าเว็บแสดงผลที่ขนาด 280 × 280 px แต่เราเตรียมภาพขนาด 280 × 280 px มาแสดง ภาพบนจอมือถือจะดูเบลอแตกเล็กน้อย จึงต้องเตรียมภาพที่ขนาด 2 เท่า (560 × 560 px) เสมอ

🧮 เครื่องคำนวณกฎทองขนาดภาพสินค้า (2x Asset Rule)
ขนาดไฟล์ภาพจริงที่ต้อง Export (Retina 2x):
560 × 560 px
เมื่อบีบอัดเป็น WebP จะหนักเพียง ~60 – 90 KB
TOPIC 3.3 • LOSSY VS LOSSLESS & THE COMPRESSION SWEET SPOT

3.3 เทคนิคการบีบอัดระดับเซียน (Finding the Sweet Spot)

การบีบอัดภาพมี 2 รูปแบบคือ 1. Lossless (ไม่สูญเสียข้อมูล ลดได้เพียง 10–20%) และ 2. Lossy (ตัดทอนเฉดสีที่ตามนุษย์มองไม่เห็น ลดขนาดไฟล์ลงได้ถึง 70–85%) ลองคลิกเลือกค่า Quality ด้านล่างเพื่อดูจุดสมดุลที่คุ้มค่าที่สุด:

Quality 100% 1,200 KB ❌
เปลืองเน็ต โหลดช้ามาก

เก็บข้อมูลเม็ดสีเกินความจำเป็นที่สายตามนุษย์แยกแยะได้

Quality 90% 450 KB ❌
ยังใหญ่เกินเกณฑ์การ์ด

เกินเพดาน 150 KB ต่อภาพสินค้า เมื่อรวมหลายชิ้นหน้าเว็บจะอืด

⭐ Quality 75%–82% 85 KB ✅
The Sweet Spot (ลดลง 90%)

สายตามนุษย์แยกความต่างไม่ออก แต่ขนาดไฟล์ลดลงกว่า 90%!

Quality 50% 35 KB ❌
บีบอัดหนักเกินไป

ภาพเริ่มเป็นปื้นสีเพี้ยน แตกเป็นบล็อกสี่เหลี่ยม (Compression Artifacts)

⚖️ เกณฑ์เพดานน้ำหนักไฟล์ภาพสำหรับเว็บไซต์ธุรกิจ (File Weight Ceilings)
1. ภาพไอคอนเวกเตอร์ (SVG) < 5 KB / ชิ้น
2. ภาพถ่ายสินค้าบนการ์ด (WebP) < 150 KB (เป้า 60–90KB)
3. ภาพแบนเนอร์ Hero (WebP) < 300 KB

ตอนที่ 4: ใบงานปฏิบัติการประจำหน่วยที่ 3 & ตารางตรวจสอบขนาดไฟล์ (File Size Audit)

สรุปภารกิจการส่งงานประจำหน่วยที่ 3 (รวม 15 คะแนน แบ่งเป็น 3 ชิ้นงาน ชิ้นละ 5 คะแนน) พร้อมตารางคำนวณการลดขนาดไฟล์ภาพ WebP และแบบตรวจสอบตนเองก่อนส่งงาน

📋 ใบงานที่ 3.1 5 คะแนน

ออกแบบโลโก้เวกเตอร์และชุดไอคอนบริการ SVG

  1. ออกแบบ โลโก้ประจำร้านค้า ธุรกิจดิจิทัลของกลุ่มตนเองในรูปแบบ Vector ชนิดข้อความผสานสัญลักษณ์ (Combination Mark)
  2. สร้างชุดไอคอนบริการประจำโซน Trust Badges จำนวน 4 รูป (จัดส่งด่วน, รับประกันสินค้า, ชำระเงินปลอดภัย, บริการ 24 ชม.)
  3. ไอคอนทุกชิ้นต้องวาดขึ้นบนโครงตาราง 24 × 24 px Grid โดยมีระยะเว้นขอบ (Padding) 2px และใช้ความหนาเส้น 2px Stroke สม่ำเสมอกันทุกชิ้น
  4. ทำการแปลงเส้นเป็นรูปร่างปิด (Outline Stroke) และส่งออก (Export) เป็นไฟล์ SVG ที่ถูกต้องตามมาตรฐาน
ชิ้นงานที่ 4: โลโก้แบรนด์ + ชุดไอคอนบริการ 4 รูป SVG
📋 ใบงานที่ 3.2 5 คะแนน

การตัดต่อ ไดคัท และรีทัชภาพสินค้าลงการ์ด

  1. คัดเลือกภาพถ่ายสินค้าจริงของร้านค้าตนเองจำนวน 4 ถึง 6 ชิ้นงาน (ภาพความละเอียดสูง)
  2. ทำการไดคัทแยกสินค้าออกจากฉากหลังเดิมด้วยโปรแกรม Adobe Photoshop โดยใช้เทคนิค Pen Tool ร่วมกับ Layer Mask ขอบของสินค้าต้องสะอาด ไม่มีขอบสีเดิมเปื้อน (Defringe & Inset 1px)
  3. สร้างเงาเสมือนจริงใต้สินค้าครบทั้ง 2 ชั้น (Contact Shadow ดำเข้มใต้ฐาน และ Cast Shadow ฟุ้งนุ่มนวลทอดตัว)
  4. ปรับสมดุลแสงสีด้วย Curves และ Vibrance ให้เข้ากับจานสี (Color Palette) ของแบรนด์ แล้วนำภาพไปวางเสียบแทนกล่องสี่เหลี่ยมสีเทาบนการ์ดสินค้าใน Figma
ชิ้นงานที่ 5: ชุดภาพสินค้าไดคัทสมบูรณ์พร้อมเงา 4–6 ชิ้น
📋 ใบงานที่ 3.3 5 คะแนน

การเพิ่มประสิทธิภาพภาพ WebP และทำตาราง File Size Audit

  1. นำภาพสินค้าไดคัททั้งหมดมาทำการ Optimize ด้วยโปรแกรม Photoshop หรือ Squoosh.app
  2. ปรับขนาดภาพตามเกณฑ์ Retina 2x (ขนาดกว้าง-ยาวไม่เกิน 800 × 800 px) และแปลงเป็นฟอร์แมต WebP (Quality 75–80%)
  3. ควบคุมขนาดไฟล์ของสินค้าทุกชิ้นให้อยู่ในเกณฑ์มาตรฐาน: ต่ำกว่า 150 KB ต่อภาพ (และภาพ Hero แบนเนอร์ต่ำกว่า 300 KB)
  4. จัดทำ ตารางบันทึกการลดขนาดไฟล์ (File Size Reduction Audit Table) ลงในไฟล์งาน Figma ตามแบบฟอร์มมาตรฐาน
