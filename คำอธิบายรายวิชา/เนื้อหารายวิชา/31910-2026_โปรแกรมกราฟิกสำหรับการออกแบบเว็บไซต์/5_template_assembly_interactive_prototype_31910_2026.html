UNIT 05 • WEBSITE TEMPLATE ASSEMBLY, RESPONSIVE TRANSFORMATION & INTERACTIVE PROTOTYPING

บทที่ 5: การประกอบแม่แบบเว็บไซต์และการทดสอบต้นแบบเชิงโต้ตอบ
(Template Assembly, Responsive & Interactive Prototype)

หน่วยการเรียนรู้บทสุดท้ายที่เป็นจุดบรรจบของกระบวนการออกแบบ UI/UX ทั้งหมด นำสินทรัพย์กราฟิกจากบทที่ 1–4 มาประกอบร่างเป็นแม่แบบหน้าแรกความละเอียดสูง (Hi-Fi Desktop 1440px) แปลงเลย์เอาต์สู่จอมือถือ (Mobile Responsive 390px) ออกแบบหน้ารายละเอียดสินค้า (PDP) พร้อมเชื่อมโยง Interactive Prototype และตรวจสอบคุณภาพ Design QA ก่อนขึ้นเวทีนำเสนอผลงาน

🎯

จุดประสงค์การเรียนรู้ประจำหน่วยที่ 5

1. ด้านความรู้ (Knowledge) 🧠
  • อธิบายหลักการประกอบแม่แบบเว็บไซต์ความละเอียดสูง (High-Fidelity Website Template Assembly) โดยบูรณาการสินทรัพย์กราฟิกทั้งหมดจากหน่วยที่ 1–4 ได้อย่างเป็นระบบ
  • วิเคราะห์กลยุทธ์การปรับเปลี่ยนเลย์เอาต์สำหรับหน้าจอมือถือ (Responsive Transformation Patterns: Stacking, Wrapping, Off-Canvas) ตามมาตรฐานอุปกรณ์พกพาได้
  • อธิบายสถาปัตยกรรมหน้ารายละเอียดสินค้า (Product Detail Page: PDP Anatomy) และเส้นทางการเดินทางของผู้ใช้ (User Journey Flow) จากหน้าแรกสู่การสั่งซื้อได้
  • อธิบายกลไกการสร้างต้นแบบเชิงโต้ตอบ (Interactive Prototyping) ได้แก่ Hotspots, Triggers, Transitions, และการตรึงแถบตำแหน่งคงที่ (Fixed/Sticky Scroll Position) บน Figma ได้
  • อธิบายมาตรฐานการเข้าถึงสากล (Web Accessibility: WCAG 2.1 AA) โดยเฉพาะเรื่องอัตราส่วนความเปรียบต่างของสี (Contrast Ratio ≥ 4.5:1) ได้
2. ด้านทักษะปฏิบัติการ (Skill) 🛠️
  • การประกอบแม่แบบคอมพิวเตอร์: ประกอบแม่แบบหน้าแรกคอมพิวเตอร์ (Hi-Fi Desktop Homepage Template 1440px) ครบทั้ง 5 โซนหลัก โดยใช้สินทรัพย์จริงทั้งหมดลงบน 12-Column Grid ได้อย่างประณีต
  • การแปลงเลย์เอาต์มือถือ: ปรับแปลงเลย์เอาต์แม่แบบหน้าแรกสู่จอมือถือ (Hi-Fi Mobile Template 390px) โดยใช้ระบบ 4-Column Grid และปรับเปลี่ยนระบบนำทางเป็น Drawer Hamburger Menu ได้อย่างสมบูรณ์
  • การออกแบบหน้ารองและผูก Prototype: ออกแบบหน้ารายละเอียดสินค้า (PDP) พร้อมเชื่อมต่อเส้นทางปฏิสัมพันธ์บนโหมด Figma Prototype ให้คลิกเปลี่ยนหน้า เปิดแผ่นเมนู และเลื่อนหน้าจอแบบ Sticky Bar ได้เสมือนเว็บไซต์จริง
  • การตรวจสอบคุณภาพ Design QA: ปฏิบัติการตรวจสอบคุณภาพการออกแบบ (Design QA Audit), ตรวจวัดค่า Contrast Ratio, จัดระเบียบเลเยอร์ 100%, และทดสอบสัมผัสใช้งานจริงผ่านแอปพลิเคชัน Figma Mirror บนสมาร์ตโฟนได้
3. ด้านจิตพิสัย (Attitude) 💎
  • มีความประณีตในการจัดระยะช่องไฟแนวตั้ง (Vertical Rhythm) และรักษาความสม่ำเสมอของ Design System ตลอดทั้งเว็บไซต์
  • มีจิตสำนึกในการออกแบบที่คำนึงถึงผู้พิการทางสายตาและผู้สูงอายุ (Digital Inclusivity)
  • มีทักษะการทำงานเป็นทีม วินัยในการส่งมอบงาน และความพร้อมในการนำเสนอผลงานระดับมืออาชีพ

PART 01 • HIGH-FIDELITY DESKTOP HOMEPAGE TEMPLATE ASSEMBLY (1440PX)

ตอนที่ 1: การประกอบแม่แบบหน้าแรกความละเอียดสูง (Hi-Fi Desktop Template 1440px)

เปลี่ยนจากพิมพ์เขียวขาว-ดำ (Low-Fi Wireframe) ไปสู่แม่แบบความละเอียดสูง (High-Fidelity Mockup) ด้วยการแทนที่กล่องสี่เหลี่ยมสีเทาด้วยชิ้นส่วนจริงที่สมบูรณ์ 100% พร้อมควบคุมจังหวะช่องไฟแนวตั้ง (Vertical Rhythm)

TOPIC 1.1 • FROM LOW-FI WIREFRAME TO HI-FI PRODUCTION TEMPLATE

1.1 การบูรณาการสินทรัพย์จริงทั้งหมดเข้าสู่พิมพ์เขียว (From Low-Fi to Hi-Fi)

หัวใจสำคัญของการประกอบแม่แบบความละเอียดสูง คือ “การแทนที่กล่องสี่เหลี่ยมสีเทาด้วยชิ้นส่วนจริงที่สมบูรณ์ 100%” ทั้ง 5 โซนบนหน้าเว็บ:

โซนบนหน้าเว็บ 📐 ชิ้นงานเดิมใน Wireframe (บทที่ 2) ✨ สิ่งที่ต้องแทนที่ใน Hi-Fi (บทที่ 5)
1. Header Navbar กล่องเทา พิมพ์ข้อความว่า [LOGO] โลโก้เวกเตอร์จริง (SVG) + เมนูมีสีประจำแบรนด์
2. Hero Section กล่องสี่เหลี่ยมสีเทามีกากบาท X ข้อความสีเทากลาง Interactive Animated Hero Banner ที่สร้างจากบทที่ 4 (พร้อมแสงเงา)
3. Product Grid การ์ดสินค้ากล่องภาพสีเทา การ์ดสินค้าจริงที่ใส่ภาพไดคัท WebP + ป้ายลดราคา + ราคาจริง
4. Trust Badges ข้อความธรรมดาไม่มีไอคอน ชุดไอคอนบริการ 4 รูป (SVG) จากบทที่ 3
5. Footer กล่องสี่เหลี่ยมผืนผ้าสีเทา ส่วนท้ายสีแบรนด์เข้ม ลิงก์แผนผังเว็บไซต์และช่องทางติดต่อครบถ้วน

TOPIC 1.2 • VERTICAL RHYTHM & 8PX BASE UNIT SPACING

1.2 กฎการคุมจังหวะช่องไฟแนวตั้ง (Vertical Rhythm & Section Spacing)

ข้อผิดพลาดที่ทำให้หน้าเว็บดูอึดอัดหรือกระจัดกระจาย คือการเว้นระยะห่างระหว่างแต่ละโซนไม่เท่ากัน ในการออกแบบระดับมืออาชีพ เราใช้ระบบ Base Unit 8px ควบคุมระยะห่างแนวตั้ง 4 ระดับ:

ระดับช่องไฟ (Vertical Rhythm Hierarchy) ขนาดพิกเซลแนะนำ (Base 8px) ตำแหน่งการใช้งานบนหน้าเว็บไซต์
1. Micro Spacing 8px ถึง 16px ภายใน Component เดียวกัน (เช่น ระยะห่างระหว่างชื่อสินค้ากับราคาในการ์ด)
2. Component Spacing 24px ถึง 32px ระหว่างการ์ดสินค้าแต่ละใบในแถวเดียวกัน หรือระหว่างแถวการ์ด
3. Sub-section Spacing 40px ถึง 48px ระหว่างหัวข้อหมวดหมู่ (H2) กับแผงการ์ดสินค้าด้านล่าง
4. Major Section Spacing ⭐ 80px ถึง 120px ระยะห่างระหว่างแต่ละโซนใหญ่ (เช่น ระหว่างโซน Hero กับโซน Product Grid)

PART 02 • MOBILE RESPONSIVE TRANSFORMATION (390PX & 4-COLUMN GRID)

ตอนที่ 2: การแปลงเลย์เอาต์แม่แบบสำหรับมือถือ (Mobile Responsive 390px)

เรียนรู้จุดตัดหน้าจอ (Responsive Breakpoints) ตารางเปรียบเทียบโครงตาราง Desktop 1440px vs Mobile 390px และ 4 กลยุทธ์การแปลงเลย์เอาต์สู่หน้าจอสมาร์ตโฟน

TOPIC 2.1 • RESPONSIVE BREAKPOINTS & 12-COL VS 4-COL GRID

2.1 ทฤษฎีจุดตัดหน้าจอ (Responsive Breakpoints) และระบบตารางมือถือ

ในการพัฒนาเว็บไซต์จริง หน้าจอจะถูกแบ่งออกเป็น 3 ช่วงขนาดหลักตามจุดตัด (Breakpoints):

1. Desktop Breakpoint
กว้างตั้งแต่ 1024px ขึ้นไป

เราใช้ขนาดเฟรมมาตรฐานยอดนิยมที่ 1440px บนโครงตาราง 12 คอลัมน์

2. Tablet Breakpoint
กว้างระหว่าง 768px – 1023px

หน้าจอแท็บเล็ตและไอแพด มักใช้โครงตาราง 8 คอลัมน์

3. Mobile Breakpoint ⭐
กว้างระหว่าง 320px – 480px

เราใช้ขนาดมาตรฐาน 390px (อิงตาม iPhone 13/14/15/16) บนโครงตาราง 4 คอลัมน์

พารามิเตอร์โครงตาราง 💻 หน้าจอคอมพิวเตอร์ (Desktop 1440px) 📱 หน้าจอมือถือ (Mobile 390px)
1. จำนวนเสาคอลัมน์ (Columns) 12 คอลัมน์ (Type: Stretch) 4 คอลัมน์ (Type: Stretch)
2. ระยะขอบซ้าย-ขวา (Margin) 80px 16px ถึง 20px
3. ช่องไฟระหว่างเสา (Gutter) 24px 12px ถึง 16px
4. พื้นที่แสดงเนื้อหาจริง (Content Area) 1280px 350px – 358px
TOPIC 2.2 • 4 RESPONSIVE LAYOUT TRANSFORMATION PATTERNS

2.2 4 กลยุทธ์การปรับเปลี่ยนเลย์เอาต์ (Responsive Layout Transformation Patterns)

เมื่อย่อจากหน้าจอคอมพิวเตอร์ 1440px ลงมาเหลือเพียง 390px บนมือถือ เราไม่สามารถ “ย่อสเกลภาพให้เล็กลงเฉยๆ” ได้ เพราะตัวหนังสือจะเล็กจิ๋วจนอ่านไม่ออก นักศึกษาต้องใช้ 4 กลยุทธ์การแปลงเลย์เอาต์:

1. Stacking (การซ้อนแถวดิ่ง)

จากเดิมใน Hero Section ที่ข้อความอยู่ซ้าย–รูปสินค้าอยู่ขวา (2 คอลัมน์คู่กัน) ──► จับรูปภาพขึ้นด้านบน และดันข้อความตกลงมาซ้อนด้านล่าง

2. Wrapping / Grid Reduction (การลดจำนวนคอลัมน์การ์ด)

จากเดิมการ์ดสินค้าเรียงแถวละ 4 ชิ้น ──► ยุบเหลือเรียงแถวละ 1 ชิ้น หรือ 2 ชิ้นต่อแถว เพื่อให้ภาพและชื่อสินค้ายังอ่านชัดเจน

3. Off-Canvas Drawer (การซ่อนเมนูลงลิ้นชัก)

แถบเมนู 5 ปุ่มแนวนอนบนคอมพิวเตอร์ ──► ซ่อนไว้ใต้ปุ่มแฮมเบอร์เกอร์ (☰) เมื่อแตะจึงสไลด์แผ่นลิ้นชักออกมา

4. Touch Target Enlargement (การขยายพื้นที่แตะ)

ปุ่มคลิกด้วยเมาส์ขนาดพอดีคำ ──► ขยายความกว้างเต็มจอ (Full Width) และมีความสูงขั้นต่ำ ≥ 48px เพื่อให้นิ้วโป้งกดง่าย

TOPIC 3.2 • 3 PILLARS OF FIGMA PROTOTYPING & STICKY POSITION

3.2 ศาสตร์แห่งการสร้างต้นแบบเชิงโต้ตอบ (Interactive Prototyping)

ต้นแบบ (Prototype) คือสิ่งที่ทำให้นักศึกษาแตกต่างจากช่างวาดรูปทั่วไป เพราะมันคือ “การจำลองซอฟต์แวร์ที่เหมือนจริงโดยไม่ต้องเขียนโค้ดแม้แต่บรรทัดเดียว” ประกอบด้วย 3 เสาหลัก:

1. Trigger (ตัวกระตุ้น)

ผู้ใช้ทำกริยาอะไร?

เช่น On Click (คลิกเมาส์/แตะนิ้ว), While Hovering (เมาส์ชี้), After Delay (รอเวลาอัตโนมัติ), On Drag (ลากนิ้วสไลด์)

2. Action (การกระทำ)

เกิดผลลัพธ์อะไรขึ้น?

เช่น Navigate to (เปิดเปลี่ยนหน้าใหม่), Open Overlay (เปิดหน้าต่างลิ้นชักเมนูลอยทับ), Scroll to (เลื่อนไปยังโซนเป้าหมาย)

3. Animation (รูปแบบการเปลี่ยน)

ขยับเปลี่ยนฉากแบบไหน?

เช่น Instant (เปลี่ยนทันที), Dissolve (จางหายข้ามหน้า), Smart Animate (วัตถุเดิมขยับแปลงร่าง), Slide In (สไลด์จากขอบจอ)

📌 ขั้นตอนการตั้งค่าแถบเมนูคงที่เมื่อเลื่อนจอ (Sticky / Fixed Scroll Position) Scroll Behavior: Fixed (stay in place)
ขั้นที่ 1 • คลิกเลือกแถบเมนู คลิกเลือกแถบ Navbar ด้านบนสุด หรือแถบปุ่มสั่งซื้อด้านล่างสุด (Bottom Action Bar)
ขั้นที่ 2 • ตรวจสอบ Constraints มองที่แผงขวามือ หัวข้อ Constraints ตรวจสอบว่าตรึงอยู่กับขอบบน (Top) หรือขอบล่าง (Bottom)
ขั้นที่ 3 • เปลี่ยน Scroll Behavior ในหัวข้อ Scroll Behavior เปลี่ยนจาก Scroll with parent ให้เป็น Fixed (stay in place) แถบจะลอยค้างอยู่กับที่แม้เลื่อนอ่านเนื้อหายาวลงมา

TOPIC 4.1 • WCAG 2.1 LEVEL AA CONTRAST RATIO AUDIT

4.1 การตรวจสอบการเข้าถึง (Web Accessibility Audit & Contrast Ratio)

การออกแบบที่ดีต้องไม่ทอดทิ้งผู้ใช้งานที่มีปัญหาด้านสายตาหรือผู้สูงอายุ มาตรฐานสากล W3C Web Content Accessibility Guidelines (WCAG 2.1 Level AA) กำหนดเกณฑ์ อัตราส่วนความเปรียบต่างของสี (Contrast Ratio) ระหว่าง “สีตัวอักษร” กับ “สีพื้นหลัง” ไว้ 3 ระดับ:

1. Body Text (< 18px) ★★★ ≥ 4.5 : 1

ข้อความทั่วไปขนาดเล็ก

ต้องมีอัตราส่วนความเปรียบต่างไม่ต่ำกว่า 4.5 : 1 เพื่อให้ผู้สูงอายุอ่านเนื้อหารายละเอียดได้ชัดเจน

2. Large Headings ★★☆ ≥ 3.0 : 1

หัวข้อใหญ่ (≥18px Bold / ≥24px)

ข้อความหัวข้อขนาดใหญ่ ต้องมีอัตราส่วนความเปรียบต่างไม่ต่ำกว่า 3.0 : 1

3. UI Components & Icons ★★☆ ≥ 3.0 : 1

เส้นขอบฟอร์มและไอคอนสำคัญ

กรอบช่องกรอกข้อมูลและไอคอนนำทาง ต้องมีอัตราส่วนความเปรียบต่างไม่ต่ำกว่า 3.0 : 1

❌ ตัวอย่างที่สอบตก (Failed AA - ห้ามทำเด็ดขาด!) Contrast 1.8 : 1
ข้อความสีเทาอ่อน (#CBD5E1) บนพื้นหลังขาว

อ่านยากมาก ผู้สูงอายุและผู้มีปัญหาทางสายตาอ่านไม่ออก

✅ ตัวอย่างที่สอบผ่าน (Passed AA - มาตรฐานสากล) Contrast 7.2 : 1
ข้อความสีเทาเข้ม #374151 บนพื้นหลังขาว

คมชัด สบายตา อ่านง่ายทุกวัย ผ่านทั้งเกณฑ์ AA และ AAA
