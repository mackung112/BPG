หัวข้อที่ 1

1. สถาปัตยกรรม Event-Driven ในระบบอัตโนมัติบนคลาวด์

ในธุรกิจระดับสากล เมื่อมีลูกค้าสั่งของและชำระเงินเข้ามา เจ้าของร้านไม่ต้องมานั่งเปิดไฟล์ Word พิมพ์ชื่อลูกค้า พิมพ์รายการสินค้า บันทึกเป็น PDF แล้วเปิดเว็บเมลแนบไฟล์ส่งให้ลูกค้าด้วยตนเอง ทุกอย่างจะเกิดขึ้นแบบอัตโนมัติบนคลาวด์ผ่าน Event-Driven Architecture (EDA)

❌ กระบวนการแบบเดิม (Manual Operations)
  • พนักงานต้องเปิดโปรแกรม Word / Excel คัดลอกเลขออร์เดอร์และชื่อลูกค้าทีละรายการ
  • เสี่ยงต่อข้อผิดพลาดในการคำนวณราคายอดรวม และการสะกดชื่อผิดพลาด (Human Error)
  • ต้อง Export เอกสารเป็น PDF แล้วเปิดโปรแกรม Mail เพื่อแนบไฟล์และส่งเอง
  • กระบวนการล่าช้า ใช้เวลา 5-15 นาทีต่อออร์เดอร์ ไม่สามารถรองรับช่วงเวลาเร่งด่วนได้
✓ สถาปัตยกรรมอัตโนมัติ (Event-Driven Cloud Bots)
  • เมื่อพนักงานกดปุ่ม "ชำระเงิน (Paid)" ระบบคลาวด์จะดักจับเหตุการณ์ทันทีแบบ Real-time
  • บอทดึงข้อมูลสินค้าจากตารางลูกเข้า Google Docs Template และเรนเดอร์ PDF แม่นยำ 100%
  • ระบบ Asynchronous ส่งอีเมลพร้อมไฟล์แนบเข้า Inbox ของลูกค้าภายใน 2-5 วินาที
  • ทำงานแบบ Serverless ตลอด 24 ชั่วโมง โดยไม่มีต้นทุนแรงงานคนเพิ่มเติม
โครงสร้างโมเดล Event - Condition - Action (ECA)
AppSheet Automation Engine
1. Event (เหตุการณ์)

ตรวจจับว่าเกิดอะไรขึ้นกับข้อมูลในตารางฐานข้อมูล:

• Adds_Only: มีการเพิ่มออร์เดอร์ใหม่
• Updates_Only: มีการแก้ไขข้อมูล เช่น เปลี่ยนสถานะเป็น Paid
• Adds and Updates: ตรวจจับทั้งการเพิ่มและการแก้ไข
• Deletes_Only: ตรวจจับการลบเรคอร์ด
2. Condition (เงื่อนไข)

ตรวจสอบว่าข้อมูลที่เปลี่ยนผ่านเกณฑ์ที่ต้องทำงานหรือไม่ (Boolean Guard):

AND(
  [Order_Status] = "Paid",
  ISNOTBLANK([Customer_Email])
)
➔ ถ้าคืนค่า TRUE: ส่งต่อไปรันภารกิจ
➔ ถ้าคืนค่า FALSE: ยุติการทำงาน ไม่เปลืองทรัพยากร
3. Action / Task (ภารกิจ)

งานที่บอทต้องทำให้สำเร็จตามลำดับขั้นตอน (Step Sequences):

Step 1: Create a new file (Compile Google Docs เป็น PDF เข้า Google Drive)
Step 2: Send an email (ส่งอีเมลแจ้งเตือนลูกค้าพร้อมแนบไฟล์ PDF)
✓ ทำงานแบบ Asynchronous ในฉากหลัง
หัวข้อที่ 2

2. การออกแบบแม่แบบเอกสาร (Document Template Pattern)

AppSheet ใช้ Google Docs เป็นเครื่องมือเรนเดอร์เอกสาร (Document Template Engine) โดยเราสามารถจัดหน้าเอกสาร ใส่โลโก้ร้าน ตกแต่งตารางเส้นขอบ และใช้ตัวอักษรที่สวยงามได้ตามต้องการ พร้อมระบบแปลงค่าแท็กตัวแปร <<[Column]>> ให้เป็นข้อมูลจริงจากฐานข้อมูล

โครงสร้างแม่แบบใบเสร็จบน Google Docs 
┌────────────────────────────────────────────────────────┐
│             ตัวอย่างเทมเพลตใบเสร็จบน Google Docs       │
├────────────────────────────────────────────────────────┤
│ [ โลโก้ร้าน ]              ใบเสร็จรับเงิน (RECEIPT)    │
│                            เลขที่บิล: <<[Order_ID]>>   │
│                            วันที่: <<[Order_Date]>>     │
│ ลูกค้า: <<[Customer_Name]>>                            │
│ เบอร์โทร: <<[Phone_Number]>>                           │
│ ────────────────────────────────────────────────────── │
│ รายการสินค้า          จำนวน       ราคา       รวมเงิน   │
│ ────────────────────────────────────────────────────── │
│ <<Start:[Related Order_Details]>>                      │
│ <<[Product_ID].[Product_Name]>>                        │
│                       <<[Quantity]>>  <<[Unit_Price]>> │
│                                         <<[Subtotal]>> │
│ <<End>>                                                │
│ ────────────────────────────────────────────────────── │
│ ยอดรวมทั้งสิ้น: <<[Total_Amount]>> บาท                 │
│ ลายมือชื่อผู้รับ: <<[Customer_Signature]>>             │
└────────────────────────────────────────────────────────┘

2.1 กฎเหล็กของแท็กวนลูป <<Start>> และ <<End>>

เมื่อคำสั่งซื้อหนึ่งใบมีรายการสินค้าหลายแถว (1-to-Many Relationship) เราไม่สามารถพิมพ์แท็กแบบคงที่ได้ จำเป็นต้องใช้แท็กคู่ขนานเพื่อสั่งให้ระบบ Compiler วนลูปสร้างแถวในตารางอัตโนมัติตามจำนวนสินค้าที่มีจริงในตะกร้า:

1 แท็กเปิดวนลูป <<Start>>
<<Start:[Related Order_Details]>>

ต้องวางไว้ที่ เซลล์แรกสุด ของแถวตารางที่ต้องการวนลูป โดยระบุชื่อคอลัมน์ความสัมพันธ์ (Reverse Reference List) ที่ AppSheet สร้างขึ้นอัตโนมัติ

2 คอลัมน์ตารางลูก & Dereference
<<[Product_ID].[Product_Name]>>

ภายในช่วงวนลูป สามารถเรียกใช้คอลัมน์ของตารางลูกได้โดยตรง เช่น <<[Quantity]>> หรือดึงข้อมูลข้ามตารางผ่าน Ref ด้วยไวยากรณ์จุดเชื่อม

3 แท็กปิดวนลูป <<End>>
<<End>>

ต้องวางไว้ที่ เซลล์สุดท้าย ของแถววนลูปเสมอ ห้ามลืมเด็ดขาด หากลืมแท็กนี้ ระบบจะไม่ทราบจุดสิ้นสุดของแถวและเกิดการวนลูปไม่รู้จบจน Compile ล้มเหลว

⚠️
ข้อควรระวังอันดับ 1 ในการสร้างเทมเพลต:

หากพิมพ์แท็กสะกดผิด เช่น ลืมวงเล็บก้ามปู <<Order_ID>> (ที่ถูกต้องคือ <<[Order_ID]>>), ลืมพิมพ์ <<End>>, หรือเว้นวรรคผิดระหว่างเครื่องหมายวงเล็บแหลม ระบบจะไม่สามารถสร้างไฟล์ PDF ได้และจะฟ้อง Template Syntax Error ทันที!

3. ขั้นตอนการสร้างบอทออกใบเสร็จและส่งอีเมล (Click-by-Click)

คู่มือปฏิบัติการอย่างละเอียดแบบคลิกต่อคลิกในการประกอบร่างระบบอัตโนมัติบน AppSheet ให้ทำงานสอดประสานกันครบวงจร:

3.1 ขั้นตอนที่ 1: สร้าง Bot ตัวใหม่ใน AppSheet Automation Workspace
  1. ไปที่เมนูแถบเครื่องมือซ้าย Automation (ไอคอนรูปสายฟ้าและหุ่นยนต์)
  2. แตะปุ่ม [+] Add Bot ➔ เลือกตัวเลือก Create a custom bot
  3. ตั้งชื่อบอทให้สื่อความหมายชัดเจน: Auto Invoice & Receipt Bot
💡 ข้อแนะนำ: การตั้งชื่อบอทอย่างเป็นระบบจะช่วยให้ทีม Agile ทำงานร่วมกันได้ราบรื่นเมื่อแอปพลิเคชันมีบอททำงานพร้อมกันหลายสิบตัวในระบบ
3.2 ขั้นตอนที่ 2: กำหนด Event (เหตุการณ์ตรวจจับ) Trigger Configuration
  1. แตะที่กล่อง Event ด้านบนสุดของแผนผังบอท
  2. Event name: ตั้งชื่อ เมื่อออร์เดอร์ชำระเงินเรียบร้อย
  3. Event type: เลือก Data Change
  4. Table: เลือกตาราง Orders
  5. Data change type: เลือก Adds and Updates
  6. ในช่อง Condition (สูตรตัวกรองเงื่อนไข): กำหนดเงื่อนไขความปลอดภัย:
AND(
  [Order_Status] = "Paid",
  ISNOTBLANK([Customer_Email])
)
*(ความหมายเชิงวิศวกรรม: บอทจะเริ่มทำงานก็ต่อเมื่อออร์เดอร์เปลี่ยนสถานะเป็น Paid เท่านั้น และต้องมีที่อยู่อีเมลลูกค้าเพื่อป้องกันข้อผิดพลาดในการส่งจดหมาย)*
3.3 ขั้นตอนที่ 3: สร้าง Task ผลิตไฟล์ PDF (Create a new file) PDF Compiler Task
  1. แตะปุ่ม Add a step ใต้กล่อง Event
  2. เลือก Create a custom step ➔ เลือกการทำงานเป็น Run a task
  3. Task type: เลือก Create a new file
  4. Table: เลือก Orders
  5. หัวข้อ Template:
    • แตะปุ่ม Create ➔ AppSheet จะสร้างไฟล์ Google Docs แม่แบบให้โดยอัตโนมัติบน Google Drive ของเรา!
    • หรือแตะปุ่ม View เพื่อเปิดไฟล์ Docs ขึ้นมาตกแต่งข้อความ วางตราสัญลักษณ์ร้าน และปรับฟอนต์เป็น Sarabun

9. ข้อผิดพลาดที่พบบ่อยและแนวทางแก้ไข (Troubleshooting & Common Pitfalls)

รวมอาการผิดปกติที่มักเกิดขึ้นในการพัฒนาระบบ Automation พร้อมการวิเคราะห์สาเหตุเชิงลึกและวิธีแก้ไขอย่างเป็นระบบ:

❌ 1. บอทไม่ยอมทำงาน หรืออีเมลไม่ส่งถึงลูกค้า

สาเหตุ: แอปพลิเคชันยังอยู่ในโหมดทดสอบ (Prototype Mode) ซึ่งระบบความปลอดภัยของ AppSheet จะส่งอีเมลออกเฉพาะไปยัง อีเมลของเจ้าของบัญชีผู้สร้างแอปเท่านั้น ไม่ส่งออกไปยังบุคคลภายนอก
วิธีแก้ไข: ให้เปิดกล่องจดหมาย Inbox ของบัญชี Gmail ที่ใช้สร้างแอป เพื่อตรวจสอบว่ามีอีเมลส่งเข้ามาหรือไม่ หากต้องการส่งหาบุคคลภายนอกต้องทำการ Deploy แอปผ่านการตรวจประเมิน

❌ 2. ไฟล์ PDF เรนเดอร์ล้มเหลว (Template Syntax Error)

สาเหตุ: พิมพ์แท็กวนลูปผิดไวยากรณ์ เช่น ลืมแท็กปิด <<End>>, พิมพ์วงเล็บก้ามปูขาดหาย หรือมีเคาะเว้นวรรคผิดรูป เช่น << Start: ... >>
วิธีแก้ไข: เปิดไฟล์ Google Docs ตรวจสอบแท็กวนลูปให้ครบทั้งคู่ <<Start:[Related ...] >> ในเซลล์แรก และ <<End>> ในเซลล์สุดท้าย

❌ 3. ตัวหนังสือภาษาไทยใน PDF กลายเป็นสี่เหลี่ยม หรือสระลอย

สาเหตุ: ใช้แบบอักษรใน Google Docs ที่เซิร์ฟเวอร์เรนเดอร์ PDF ของ AppSheet ไม่รองรับ เช่น ฟอนต์เริ่มต้นแบบตะวันตก
วิธีแก้ไข: กด Ctrl+A คลุมข้อความทั้งหมดใน Google Docs แล้วเปลี่ยนแบบอักษรเป็น Sarabun หรือ Prompt

❌ 4. ส่งอีเมลซ้ำหลายฉบับจากการกดอัปเดตข้อมูลครั้งเดียว

สาเหตุ: ตัวกรอง Condition กำหนดไว้กว้างเกินไป เช่น เช็คแค่ [Order_Status] = "Paid" เมื่อใดก็ตามที่มีการแก้ข้อมูลช่องอื่นในบิล บอทก็จะส่งอีเมลซ้ำอีกรอบ
วิธีแก้ไข: ใช้ฟังก์ชันตรวจจับสถานะการเปลี่ยนค่าแบบเจาะจง: AND([_THISROW_BEFORE].[Status] <> "Paid", [_THISROW_AFTER].[Status] = "Paid")
